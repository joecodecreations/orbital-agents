# Orbital Agents — architecture and contracts

This file is the contract every component is built against. If code and this file disagree, fix one of them in the same change.

## The pieces

| Piece | What it is | Where in the repo | Runs on |
|---|---|---|---|
| **Hub** | FastAPI server: the data API the apps read (sections, blocks, alerts, actions), the satellite registry and agent relay, the tracker relay, the Agent desk | `orbital/hub/` | the primary machine |
| **Satellite service** | Small server that starts agent CLIs (claude, codex, grok, gemini…) on request and reports jobs | `orbital/satellite/` | every machine, the hub included |
| **Scheduler** | Runs data feeds on a timetable and pushes their output to the hub | `orbital/scheduler/` | the hub |
| **Watchdog** | Health checks, restarts, log and data trimming (self-healing) | `orbital/scheduler/watchdog.py` | every machine |
| **Agent Satellite Tracker** | Floating macOS panel showing what every agent is working on, plus the `orbital-track` CLI agents report with | `apps/tracker/` (Swift package) | every Mac |
| **Orbital Agents app** | iPhone / iPad app and the same target built for Mac Catalyst: dashboard, alerts, agents and satellites, tracker, Agent desk | `apps/orbital-app/` (Xcode project generated by a script) | iPhone, Mac |
| **Orbital Agents Browser Controller** | Chrome extension + local bridge so agents can drive real Chrome tabs, here or on another machine over Tailscale | extension `browser-extension/`, bridge `orbital/browser/` | any machine with Chrome |
| **CLI** | `orbital` — status, doctor, logs, config, push data, jobs (scheduler), satellite / satellites, agents, browser, services, skills, test | `orbital/cli/` (one file per subcommand in `orbital/cli/commands/`) | every machine |
| **Setup wizard** | `./setup` — asks the questions, writes config and secrets, installs services, builds apps, pairs satellites | `setup`, `orbital/wizard/` | every machine |
| **Skills** | Instructions AI agents load to use the system | `skills/` | installed into ~/.claude, ~/.codex, ~/.grok, ~/.gemini |

Names, exactly: **Orbital Agents** (the iPhone/Mac app and the project), **Orbital Agents - Agent Satellite Tracker** (the floating panel; the bar shows "Agent Satellite Tracker"), **Orbital Agents Browser Controller** (extension + bridge), **orbital** (CLI), **orbital-track** (tracker CLI).

## Roles and machines

- **Hub**: the first machine set up. Runs hub + scheduler + watchdog + satellite service + tracker (+ browser bridge if Chrome is used there).
- **Satellite**: any other machine. Runs satellite service + watchdog (+ tracker on a Mac, + browser bridge if wanted). The wizard finds the hub over Tailscale and joins it.
- Every machine runs the satellite service, so "run an agent on machine X" works the same for the hub and for satellites. The hub's own satellite joins it automatically.

## Files on disk (per machine)

Everything outside the repo lives in `ORBITAL_HOME` (default `~/.orbital-agents`, mode 0700). Code: `orbital/core/paths.py`.

```
~/.orbital-agents/
  config.toml            all settings (see config/orbital.example.toml)        ← humans edit this
  secrets.env            passwords, tokens, API keys (0600)                     ← orbital/core/secrets.py
  config.resolved.json   merged settings + paths, for the Swift apps (no secrets)
  jobs.json              scheduler timetable (feeds)
  apns.p8                optional: Apple push key (0600), only with notifications.apns = true
  data/hub/              sections/, media/, actions/, alerts.json, devices.json, prefs.json, pulse.json,
                         sessions.json, identity.json, satellites.json, desk
  data/tracker/          items.json, settings.json, inbox/, hub-outbox/, media/YYYY-MM/  (tracker app is the only writer of items.json)
  data/scheduler/        state.json, settings.json, requests/, out/<job>.log, runs/<job>.log
  data/satellite/        identity.json, heartbeat.json, jobs/<job>.json, out/<job>.log
  data/browser/          staged/, captures/
  data/feeds/            state the example feeds keep between runs (chart history)
  logs/<component>.log   JSON lines, rolled by size   (+ <component>.stderr.log from launchd/systemd, trimmed by the watchdog)
  run/                   pid, port and heartbeat files (hub.json, tracker.json, bridge.json, satellite.json,
                         scheduler.json, watchdog.json)
```

## Ports (defaults, all in config.toml)

| Port | Service | Binds |
|---|---|---|
| 7700 | hub | 0.0.0.0, but only loopback + Tailscale ranges are answered (`hub.allow_networks`) |
| 7701 | tracker app API | 127.0.0.1 only |
| 7702 | tracker speech sidecar (optional) | 127.0.0.1 only |
| 7703 | browser bridge | 127.0.0.1, or this machine's Tailscale IP when `browser.bind = "tailscale"` |
| 7704 | satellite service | this machine's Tailscale IP + 127.0.0.1 when `satellite.bind = "tailscale"` |

Tests never use 7700–7704: they take a free port from the OS (or 17700–17799) and a temp `ORBITAL_HOME`.

## Config and secrets

- `orbital/core/config.py` holds DEFAULTS (every setting). `load_config()` merges `config.toml` over them. Read with `cfg.get("hub.port")`.
- `cfg.write_resolved()` writes `config.resolved.json`. Swift code reads that file (path: `$ORBITAL_HOME/config.resolved.json`, `ORBITAL_HOME` env var or `~/.orbital-agents`).
- Secrets are only in `secrets.env` via `orbital/core/secrets.py` (`Secrets().get("ORBITAL_AUTOMATION_TOKEN")`). Never in config.toml, never in logs (use `secrets.mask()`), never in the repo.

## Logging

- `from orbital.core import get_logger; log = get_logger("hub")` → `logs/hub.log`, JSON lines `{"ts","level","component","msg",...}`, `RotatingFileHandler` with `logging.max_bytes` / `logging.backups`.
- Swift apps write the same JSON-line format to `logs/tracker.log` / `logs/app.log` with the same size rule (roll to `.1`, keep `backups`).
- launchd/systemd stdout+stderr go to `logs/<component>.stderr.log`; the watchdog truncates them past `logging.max_bytes` and deletes rolled files older than `logging.retention_days`.
- `orbital logs [component] [-f] [--level WARNING] [--since 1h]` reads and merges them.
- Never log secrets, tokens, passwords, or full request bodies.

## Auth

| Caller → callee | Credential |
|---|---|
| App (iPhone/Mac) → hub | `POST /v1/login {username,password}` → session token (Bearer). Username/password: `ORBITAL_HUB_USERNAME/PASSWORD` |
| Hub → Apple push (optional) | ES256 provider token from `~/.orbital-agents/apns.p8` + `APNS_KEY_ID`/`APNS_TEAM_ID`, only when `notifications.apns = true` |
| Feeds, scripts, CLI → hub | `Authorization: Bearer $ORBITAL_AUTOMATION_TOKEN` |
| Satellite → hub (join, heartbeat, tracker relay) | join once with `X-Orbital-Join-Token: $ORBITAL_JOIN_TOKEN`; afterwards `Authorization: Bearer <hub_token issued at join>` |
| Hub → satellite | `Authorization: Bearer <satellite token sent at join>` (`ORBITAL_SATELLITE_TOKEN` on the satellite) |
| Anyone → remote browser bridge | `Authorization: Bearer $ORBITAL_BROWSER_TOKEN` (loopback calls from the extension need none). There is one browser token for the whole fleet: the hub hands its `ORBITAL_BROWSER_TOKEN` to every satellite at join, and the hub relay sends it |
| Agents → tracker | `orbital-track` → tracker loopback API (no token; loopback only). On a machine without a tracker it relays through the hub. |

Every server also checks the client IP against its allow list (`orbital/core/net.allowed`). The hub also accepts the token as `X-Orbital-Token: <token>`, and on the `/v1/live` websocket as `?token=`.

## Hub HTTP API (base `http://<hub>:7700`)

Data API (ported from the original project, renamed): `GET /v1/health`, `GET /v1/hub/info` (no auth; `{"service":"orbital-hub","name","version","hub_id","machine"}` — used for discovery), `GET /v1/contract`, `POST /v1/login`, `POST /v1/logout`, `GET /v1/catalog`, `GET|PUT|DELETE /v1/sections/{id}`, `POST /v1/sections/{id}/ops`, `POST /v1/sections/{id}/validate`, `GET|POST /v1/alerts`, `POST /v1/alerts/ack`, `POST /v1/alerts/retract`, `GET|POST /v1/prefs`, `POST|GET /v1/sections/{id}/actions`, `POST /v1/sections/{id}/actions/results`, `POST /v1/media`, `GET /v1/media/{id}`, `POST /v1/devices`, `GET /v1/sync`, `GET /v1/jobs` + run/cancel/settings/log (scheduler), `GET|POST /v1/desk…` (Agent tab), `GET /v1/tracker/items`, `GET /v1/tracker/items/{id}`, `GET|POST /v1/tracker/settings`, `GET /v1/tracker/media/{item}/{media}`, `WS /v1/live`.

Satellites and agents (new):

| Method | Path | Who | Body / result |
|---|---|---|---|
| POST | `/v1/satellites/join` | satellite, `X-Orbital-Join-Token` | `{name, machine, host, ip, port, os, satellite_token, capabilities:{agents:[...], browser:bool, browser_port, tracker:bool}, version}` → `{satellite_id, hub_token, hub_id, heartbeat_seconds, browser_token}`; `browser_token` is the fleet-wide `ORBITAL_BROWSER_TOKEN` (the hub creates it if missing), which the satellite stores; a rejoin refreshes it |
| POST | `/v1/satellites/heartbeat` | satellite, hub_token | `{satellite_id, capabilities, running_jobs}` → `{ok}`; offline after 3 missed beats |
| GET | `/v1/satellites` | app/CLI | list with status `online|offline`, last_seen, capabilities |
| DELETE | `/v1/satellites/{id}` | app/CLI | remove |
| POST | `/v1/satellites/{id}/agents/run` | app/CLI | `{agent, prompt, cwd?, title?}` → relayed to the satellite → `{job_id, satellite_id}`; prompt limits below |
| GET | `/v1/agents/jobs` | app/CLI | jobs across all satellites (cached from heartbeats + direct reads) |
| GET | `/v1/satellites/{id}/agents/jobs/{job}` (+ `/log`, `/cancel`) | app/CLI | relayed |
| POST | `/v1/satellites/{id}/browser/{command}` | app/CLI | relayed to that machine's browser bridge with the browser token |
| POST | `/v1/tracker/command` | satellite (hub_token) / automation token | relays an `orbital-track` command to the hub's tracker; a satellite's command without `machine` gets that satellite's machine name. `/v1/tracker/items` rows carry the `machine` |
| GET | `/v1/satellites/{id}` (+ `/ping`, `/agents/jobs`) | app/CLI | one satellite; `{id}` also matches the machine or display name |

Other hub endpoints: `GET|POST /v1/pulse` (lightweight heartbeat metrics), `/v1/stt/models…` and `/v1/speech/status|tts|tts/stream` (optional speech; status lists the `[speech.voices]` with each language's default, and tts with no `reference_id` uses the default for its `language`), `POST /v1/desk/voice-log`. Error bodies carry `error` and `detail`. A satellite's own auth failure is returned as 502 "join it again", never as the caller's 401. A satellite's `hub_token` may also list satellites and use the agent and browser relays, so any joined machine can orchestrate the others. Besides that it may only post alerts (the hub stamps them with the machine name and prefixes their ids), use the tracker relay, and read or set the tracker's evidence setting; it cannot read or write sections, actions, media, the desk or sync, and cannot remove satellites. `GET /v1/satellites/{id}/agents/jobs/{job}/log?format=text` returns the log as plain text. `GET /v1/hub/info` and `GET /v1/health` also carry `apns: {enabled, configured, environment}`.

## Satellite service API (base `http://<machine>:7704`, Bearer satellite token)

`GET /v1/health` (no auth: `{"service":"orbital-satellite","machine","version","agents":[available agent names]}`), `GET /v1/agents` (every configured agent and whether it is installed here), `POST /v1/agents/run {agent, prompt, cwd?, title?, track?:true}` → `{job_id}`, `GET /v1/agents/jobs`, `GET /v1/agents/jobs/{id}` (status `queued|running|done|failed|cancelled`, exit_code, started/finished, output_tail), `GET /v1/agents/jobs/{id}/log`, `POST /v1/agents/jobs/{id}/cancel`.

Rules: argv from `[agents.<name>].command` with `{prompt}`/`{cwd}` substituted, never a shell; `cwd` must be inside `satellite.workdirs`; at most `satellite.max_concurrent_jobs`; killed after `job_timeout_minutes`; output kept under data/satellite with a size cap; each job reports to the tracker (`orbital-track start/done`, agent label = agent name, title = job title) when `track` is true. An agent whose executable isn't on PATH is not listed as available.

Prompt limit: `orbital/core/limits.py` `MAX_PROMPT_CHARS = 100_000`, shared by the hub relay, the satellite's HTTP model and its job runner. A longer prompt gets 413; an empty one 400.

## Discovery and joining (setup wizard, satellite role)

1. `tailscale status --json` → online peers (`orbital/core/net.tailscale_peers`).
2. For each peer, `GET http://<peer dns or ip>:<hub.port>/v1/hub/info` (1.5 s timeout). Hubs answer with `"service":"orbital-hub"`.
3. Pick the hub (auto when exactly one). Ask for the join token, which the hub's wizard printed and `orbital satellites invite` prints again.
4. Generate this machine's satellite token, `POST /v1/satellites/join`, store `ORBITAL_HUB_TOKEN` and the fleet's `ORBITAL_BROWSER_TOKEN` from the answer, write `hub.url`, `system.role = "satellite"`. When the browser token changed, `orbital satellite join` and the wizard restart the browser bridge (it reads its token at start).
5. Install services, start the heartbeat. `orbital satellites` on the hub now lists the machine.

## Browser controller

- Extension (`browser-extension/`, MV3, name "Orbital Agents Browser Controller") always talks to the **local** bridge `http://127.0.0.1:<browser.bridge_port>` (port set in the extension's options, default 7703).
- Bridge (`orbital/browser/`, `python -m orbital.browser.server`) queues commands for the extension and returns results: `GET /health`, `GET /status`, `POST /command {action, params}` plus the existing tab/navigate/click/type/eval/network/upload commands.
- Other machines reach a bridge only through `browser.bind = "tailscale"` + `ORBITAL_BROWSER_TOKEN` (one value for the fleet, handed out at join), or through the hub relay `/v1/satellites/{id}/browser/{command}`.
- CLI: `orbital browser [--node <machine>] [--via auto|direct|hub] [--session NAME] status|nodes|tabs|navigate URL|click SEL|type SEL TEXT|eval JS|screenshot|…` (full list: `orbital browser --help`, `docs/BROWSER_CONTROLLER.md`). Nodes = joined satellites with `capabilities.browser`, plus `local`.

## Data pipeline (what the app shows)

Feeds push **sections**. A section is a page in the app made of **blocks**: heading, paragraph, bullets, callout, metrics, key_value, table, timeline, divider, chart, image, hero, buttons, progress, status, links, product, ledger, tasks, series, insight_cards and videos (`orbital/hub/contract.py` `APP_BLOCKS`). On `tabs` and `sidebar` layouts the section's own `blocks` are drawn above the tab or node content; ops without `node_id`/`tab_id` address them on every layout. Buttons tap to a URL, a page, the Desk (`agent`), a pre-filled Run agent sheet (`run_agent`), or post an action back to the feed (`post`). Sections can be grouped into **spaces** (the app's home tiles: a project, a team, a household, a server fleet — anything). Alerts raise notifications. Actions let the phone send a button press back to the feed. Contract, schema and examples: `docs/DATA_PIPELINE.md`, `schema/*.json`, `feeds/examples/`. Feeds push with `orbital push`, the Python SDK (`orbital.feeds`), or plain HTTP with the automation token. No example in the repo may refer to a real person's private matters; use generic domains (home server, website uptime, GitHub repo, weather, fitness, sales dashboard, reading list).

## Services (run at login / restart, self-healing)

macOS LaunchAgents in `~/Library/LaunchAgents/`, label prefix `io.orbitalagents.`: `hub`, `scheduler`, `satellite`, `browser-bridge`, `watchdog` (StartInterval), `tracker` (opens the app at login; KeepAlive on crash only). Linux: systemd user units `~/.config/systemd/user/orbital-<name>.service` (the watchdog as a oneshot plus `orbital-watchdog.timer`; there is no tracker on Linux). Windows: Task Scheduler tasks `\OrbitalAgents\orbital-<name>` that run at logon as the user (no admin), each running `pythonw -m orbital.services.winrun` with a run spec in `%LOCALAPPDATA%\OrbitalAgents\services\orbital-<name>.json`. That supervisor sets the environment, writes `logs/<name>.stderr.log`, restarts the service 10 s after it exits, runs the watchdog every interval, and holds the child in a kill-on-close job object; when Windows refuses a logon task it falls back to an `HKCU\…\Run` value. `orbital services install|uninstall|status|start|stop|restart [name]`. Daemons use `KeepAlive`/`Restart=always` (10 s throttle); the watchdog adds health-based restarts and raises a hub alert when it restarts something. Service stdout/stderr go to `logs/<name>.stderr.log`.

## Coexistence

Labels (`io.orbitalagents.*`), ports (7700–7704), bundle ids (`<bundle_prefix>.orbitalagents`, `<bundle_prefix>.orbitalagents.tracker`), data (`~/.orbital-agents`) and CLI names (`orbital`, `orbital-track`) are all distinct, so Orbital Agents can run beside other tools on the same machine. The wizard never edits files it didn't create, and agent-rule blocks are fenced with `ORBITAL-AGENTS:BEGIN/END`.

## Tests

- `make test` → pytest unit + integration (temp ORBITAL_HOME, free ports; starts hub + satellite in-process or as subprocesses), Swift `swift build`/`swift test` for the tracker, simulator build of the app, extension lint.
- `orbital test --live` → operational checks on the running install: services up, hub auth, section round trip, alert, tracker round trip, scheduler, every satellite (ping + echo agent job), every browser node (bridge + extension connected + open a tab), log rotation config.
- `tests/test_public_safety.py` fails on credentials or private data in tracked files.
